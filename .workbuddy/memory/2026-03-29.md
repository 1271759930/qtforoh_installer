# 2026-03-29 工作日志

## 项目创建

### 任务描述
用户请求开发一个CLI工具，用于安装鸿蒙版本的Qt框架。工具需要：
- 交互式输入Qt源码路径、鸿蒙SDK路径、Qt安装路径
- 自动下载make工具和perl
- 使用这两个工具完成Qt框架的编译安装

   - 查阅官方文档：https://wiki.qt.io/Building_Qt_for_HarmonyOS

   - 确定技术栈：Python 3.12+ + Click + Questionary + Rich

2. **项目架构设计**

   - 创建项目基础文件：pyproject.toml, requirements.txt, .gitignore

   - 创建MEMORY.md：项目长期记忆

6. **运行问题修复**
   - 用户报告无法运行qtohos-installer命令
   - 问题原因：pip不在PATH中，需要使用python -m pip
   - 问题原因：qtohos-installer.exe安装在Scripts目录，不在PATH中
   - 解决方案：使用python -m src.cli运行
   - 修复quick_start.py，使用模块方式运行
   - 更新README.md，添加正确的运行方式说明

7. **交互式输入问题修复**
   - 用户报告第一步一直转圈，无法输入
   - 问题原因：questionary.path()在Windows平台不稳定
   - 解决方案：改用questionary.text()实现路径输入
   - 修改interactive.py，使用更可靠的文本输入方式

8. **编码问题修复**
   - 运行时出现UnicodeEncodeError
   - 问题原因：Windows PowerShell使用GBK编码，无法显示Unicode字符
   - 解决方案：在cli.py中设置UTF-8编码
   - 添加sys.stdout/stderr编码重配置
   - 测试验证：check命令正常运行，Unicode字符正确显示

9. **交互式输入改进**
   - 用户反馈输入时没有回显，希望有更明显的输入框
   - 问题原因：questionary在Windows平台回显不明显
   - 解决方案：使用Rich Prompt替代questionary
   - 修改interactive.py：
     - 使用Rich Prompt.ask()替代questionary.text()
     - 使用Rich Confirm.ask()替代questionary.confirm()
     - 使用数字选择替代questionary.select()
     - 添加明显的输入框样式（Panel）
     - 输入提示使用绿色加粗字体
     - 添加选项列表显示
   - 效果：输入框更明显，回显清晰，用户体验更好

10. **移除Progress动态刷新**
    - 用户反馈输入仍然没有回显，没有光标位置
    - 问题原因：installer.py中的Progress动态刷新干扰输入
    - 问题现象：显示"⠏ Collecting configuration..."动态刷新
    - 解决方案：移除Progress，改用简单的状态提示
    - 修改installer.py的run()方法：
      - 移除Progress上下文管理器
      - 使用简单的console.print显示步骤
      - 每个步骤显示清晰的标题
    - 效果：输入时不再有干扰，光标和回显正常显示

11. **修复安装失败问题**
    - 问题1：UnicodeDecodeError - GBK编码无法解码winget输出
      - 原因：subprocess.run使用text=True时默认用GBK解码
      - 解决：添加encoding='utf-8'和errors='ignore'参数
      - 修改位置：downloader.py中的winget和choco命令
    - 问题2：Perl下载404错误
      - 原因：Strawberry Perl下载URL不可用
      - 解决：改用winget安装StrawberryPerl.StrawberryPerl
      - 优势：更可靠，自动处理PATH配置
      - 备选：提供手动安装选项
    - 测试结果：
      - 编码问题已解决，无UnicodeDecodeError
      - 安装逻辑正确，提供手动安装选项
      - 创建test_download.py测试脚本验证修复

12. **添加工具路径配置功能**
    - 用户需求：如果已安装make和perl，可以配置路径避免重复安装
    - 实现方案：
      1. 修改config.py的InstallConfig，添加make_path和perl_path字段
      2. 修改interactive.py，添加prompt_tool_paths()方法询问工具路径
      3. 修改downloader.py，优先使用配置的路径
      4. 修改installer.py，传递配置的工具路径
      5. 更新config.example.yaml，添加工具路径配置示例
    - 使用方式：
      - 交互式：在Step 7询问是否已安装工具，输入路径
      - 配置文件：在config.yaml中设置make_path和perl_path
    - 优势：
      - 避免重复安装已有工具
      - 支持自定义工具位置
      - 灵活性更高

1. **语言选择**: Python
